# P1: PSNR 교체

**목표**: PSNR 계산 함수를 스스로 작성한 코드로 교체한다.

## 식과 기호 설명

PSNR은 픽셀이 표현할 수 있는 최댓값의 제곱을 MSE로 나눈 뒤 데시벨로 표현한 것이다.
PSNR = 10 * log_10(최댓값^2/MSE)

여기에서 MSE는 각 픽셀의 원본과의 차이를 제곱한 값을 전부 합한 뒤, 픽셀 수로 나누어 평균을 낸 지표다.

MSE는 상황에 따라 너무 큰 차이로 벌어질 수 있다. 그래서 넓은 범위 비율을 보기 쉬운 수로 압축하기 위해 로그와 dB 단위를 쓰는 PSNR을 자주 사용한다.

## 검증 방법과 결과, 불일치 원인과 AI에게 받은 힌트

패치 5개를 이미 만들어진 patches.npy에서 읽어온다. 그 패치들을 인수 형식에 알맞게 변환한 뒤, '약한 노이즈 추가하기', '강한 노이즈 추가하기', '밝기 일정하게 올리기', '일정한 영역 훼손하기', '원본 그대로 두기' 변화를 거친 예측 이미지를 각각 1장씩 총 5장 만든다. 그 다음 원본과 예측 텐서를 직접 만든 함수와 AI가 만든 함수에 인수로 넣고 값을 출력한다. 또한, 소수점 넷째 자리 같은지를 차이 비교 방식으로 측정한다. 이후 최대 차이와 통과/실패 여부를 추가로 출력한다. 실행 출력은 verification/에 번호를 붙인 로그 파일로 저장한다.

MSE가 0이 된 상황, 즉 분모가 0인 문제를 막으려면 하한값이 필요하다는 것을 알았을 때, 이것이 결과에 영향을 줄 수 있다는 것을 인지했다. 따라서 하한값은 AI가 작성한 코드와 같아야 공정한 비교가 가능하므로 값만 따로 미리 참고하였으며 1회차 결과에도 이러한 값이 반영되었다.

- 1회차 결과
```
tensor([  5.4288,   6.9226,  13.9794,  21.9817, 100.0000], dtype=torch.float64)
tensor([  5.4288,   6.9226,  13.9794,  21.9817, 148.1308], dtype=torch.float64)
실패(최대 차이:48.1308)
```
(1회차 실패 로그의 원본 파일은 덮어쓰기로 소실되었고, 위 출력은 그때 옮겨둔 것이다.)

불일치 원인은 PSNR과 MSE의 기준에 쓰인 MAX, 즉 최대값이 0 ~ 255가 아닌 0 ~ 1으로 봤기 때문이다.
AI는 힌트로 역산 과정을 풀어낼 것을 제시했으나, 다른 방식으로 원인을 발견했다. 100과 148.13이라는 값에 의미가 있을 것이라는 의심이 들었고, 값의 범위를 좁힌 결과 10 * log_10(255 ** 2)가 48.13인 것을 발견함으로써 기준의 문제임을 확신했다. 그리고 이를 해결하기 위해 기존 MSE를 구하던 코드를 수정했다. ((255 기준)/255)의 제곱의 분모는 255의 제곱이기 때문에, 다시 255 최댓값의 제곱을 곱해서 분모를 없애 255 기준을 맞춰주었다.

- 2회차 결과
```
tensor([  6.6709, 148.1308,   7.9588,  10.4395, 148.1308], dtype=torch.float64)
tensor([  6.6709, 148.1308,   7.9588,  10.4395, 148.1308], dtype=torch.float64)
통과
```

2회차는 통과처럼 보였지만, 강한 노이즈 차이가 있을 두 번째 쌍이 원본과 그대로인 다섯 번째 쌍과 같은 수치를 보였다는 점에서 올바른 검증 과정이 아니었다. 실제로 원본 그대로인 쌍이 2개였으며, 강한 노이즈가 약한 노이즈 쌍을 덮어쓰고 있던 것이다. 코드에서는 단순 인덱스 지정 문제였으며, 이를 발견해 수정했다. (success1~4.txt는 쌍 구성 버그가 있던 버전의 로그였음을 밝힌다.)
